# LexFlow 筆記：工具介紹

給接手協助修改這個工具的 AI 看。使用者是準備學測的台灣學生，一律用繁體中文溝通，不要中途換成英文。他不寫程式，改動前先用白話說明要改什麼，重要的視覺改動先做示意圖給他看再動手。

---

## 一、這是什麼

一個 Android App（使用者的手機是 Samsung Galaxy S25+），用來讓他每天自然地複習用 LexFlow 背單字時存下的英文用法筆記。

**使用者的日常流程**

1. 主畫面上有一個小工具，顯示一則筆記的**標題和摘要**。
2. 點小工具，打開**詳細頁**，讀完整的筆記。
3. 讀完按右下角圓形的 **Done**，跳出一句英文短句，頁面自動關閉回到主畫面，小工具已經換成下一則。

**另外兩份文件**
- `docs/筆記整理提示詞.md`：整理新筆記、上傳的規則。新增或修改筆記內容時看這份。
- 本文件：修改 App 本身時看這份。

## 三、目前定案的設定

### 主畫面小工具（`res/layout/widget.xml`、`res/values/colors.xml`）

- 深色實心卡片，底色 `#1E2023`，圓角 28dp。和使用者主畫面上三星日曆小工具的風格一致。
- 標題：白色、粗體、一行，最大 29sp，太長時自動縮小到最小 18sp，再長就切成「…」。
- 摘要：淺灰 `#BCC1C8`，16sp，最多 3 行。
- 標題和摘要間距 13dp，整塊文字上下置中，四邊留白。
- 不顯示分類標籤。
- 點小工具打開詳細頁。

### 詳細頁

- 背景：ChronoFlow 的暖白紙色漸層（`#F9F8F5` → `#FCFAF6`）。
- Blob 背景：從使用者另一個專案 ChronoFlow 的 Cosmos 分頁搬過來（`NoteBlob.java` 有完整說明）。4 顆模糊色塊（蜜杏、藕荷、抹茶綠、霧霾藍），透明度 12–18%，慢慢飄、碰邊反彈、特定顏色互相柔和推開。為手機調整過：大小是螢幕寬的 50–60%，速度是原版的一半。
- 頂部：分類標籤 + 標題（31px），然後直接進正文。**詳細頁不顯示摘要**，摘要只在小工具上。
- 正文 18px，小標用墨灰色 `#3A3F47`。
- Done：右下角圓形按鈕，每次打開從「墨水色組」隨機選一色：`#2E4A6B` `#1F5F5B` `#5B3A63` `#8A4B2A` `#4F5B2E` `#3A3F47`。
- 按 Done 後：從下面 14 句隨機閃一句，然後關閉頁面。
  `Confirmed.` `Noted.` `Got it.` `Filed away.` `Saved.` `Locked in.` `One more down.` `In the bag.` `Nice.` `Sharp.` `Well done.` `Keep going.` `Onward.` `Another one for the essay.`

### 排程規則（`Store.java`）

- 小工具一次顯示一則，按 Done 才換。
- 按過 Done 的筆記隔 1、3、7、14 天回來，之後每 30 天一次。
- 一則放 24 小時沒按，自動換下一則；被換掉的排到後面，不算讀過。
- 下一則的順序：到期該複習的 → 還沒讀過的 → 最快到期的。
- **每日上限**：設計是一天 5 則，讀滿後小工具只顯示「That's all for today. / See you tomorrow.」，點了也打不開詳細頁，半夜 12 點解除。
  - **目前裝的是測試版，沒有上限。** 上限由打包參數 `dailyLimit` 控制（`app/build.gradle`，預設 0 = 無上限）。要改回 5：在 `.github/workflows/app.yml` 的 gradle 指令加上 `-PdailyLimit=5`，或把 `app/build.gradle` 的預設值改成 `'5'`。

### 同步

- App 從 `https://raw.githubusercontent.com/Chun-Hsuan/lexflow-widget/main/notes.json` 下載筆記。
- 打開詳細頁時一定同步；小工具每 30 分鐘更新一次時，若距上次同步超過 6 小時也會同步。
- 筆記只改內容不改 ID，進度保留；刪掉的筆記就不會再出現。

## 四、怎麼改 App、發新版

1. 改 `app/` 底下的程式或設定。
2. 推到 `main`。`Build app` 會自動跑：先跑單元測試，再打包、簽章，發布到 Releases（版本號 `v1.0.<次數>`）。約 2 分鐘。
3. 確認成功：`gh run list -R Chun-Hsuan/lexflow-widget`，或 `gh run watch <id> --exit-status`。
4. 把下載連結給使用者（**每次都要貼出連結**，不要只說「同一個連結」）：
   `https://github.com/Chun-Hsuan/lexflow-widget/releases/latest/download/LexFlow-Widget.apk`
5. 使用者在手機下載、按「更新」覆蓋安裝，進度會保留。裝完從 App 圖示打開一次，小工具會重畫成新樣子。

**注意**：雲端環境連不到 Android 打包工具，不能在本機打包，一律靠 GitHub Actions。排程邏輯可以在本機用簡單的替身類別編譯 `Store.java` 和 `StoreTest.java` 先測。

## 五、不能亂動的地方

- **筆記的英文代號（檔名去掉編號的部分）**：就是 ID，改了進度會歸零。
- **`signing/release.jks` 和 workflow 裡的密碼**：換了簽章，手機上就無法覆蓋更新，只能刪掉重裝，進度全部消失。
- **`applicationId`（`com.lexflow.widget`）**：同上。
- **版本號**：用 GitHub 的執行次數自動遞增。如果把 `app.yml` 改名或重建，次數會從 1 重來，新版本號會比手機上的小，無法更新。
- 簽章檔放在公開 repo 裡，是為了方便打包的取捨。風險很低（要有人做假更新檔、還要使用者自己去裝）。使用者如果想更保險，可以把它移到 GitHub Secrets（`SIGNING_KEY_B64`、`KEYSTORE_PASSWORD`，workflow 已經支援），再從 repo 刪掉。

## 六、使用者已經否決過的設計（不要再提）

- 按 Done 後提示「N 天後再出現」：他覺得這是在講系統排程，不喜歡。
- 詳細頁顯示「已了解 0/28」這類進度：不需要。
- 每日沒有上限：正式版要有 5 則上限（目前的無上限只是測試）。
- 小工具半透明底：在照片桌布上很髒、很突兀。Android 一般 App 的小工具做不到毛玻璃模糊。
- 小工具字放很大、塞滿格子：看起來像字牆，和其他小工具格格不入。
- 筆記裡的 emoji、誇張詞、比喻口訣。

## 七、安裝和手機設定（使用者遇到問題時）

- 下載卡住：多半是 Chrome 在等確認，看下載清單或通知欄；不行就改用 Samsung Internet。
- 無法安裝：允許瀏覽器安裝未知應用程式；Play 安全防護選「仍要安裝」；三星「自動封鎖程式」要先關掉。
- 小工具不會自己換：設定 → 應用程式 → LexFlow 筆記 → 電池 → 不受限制。
- 小工具沒更新成新樣子：從 App 圖示打開一次，或長按小工具稍微拉一下大小。
